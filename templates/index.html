Welcome

A subprocess bridge between SillyTavern and Claude Code CLI. SillyTavern sends OpenAI-compatible requests to this server; the bridge translates them, frames SillyTavern's prompt for the CLI, pipes the result through claude -p, and returns the response. Everything in this interface controls how that translation works.

Getting started

Endpoint
Point SillyTavern's Chat Completion API (Custom, OpenAI-compatible) at http://localhost:5001/v1. When the bridge runs with BRIDGE_API_KEY set, use that key as the API key.
Model
Choose the model in the Settings tab, or pick "Use SillyTavern's model" there to take the one selected in SillyTavern's connection.
Start command
Run run_bridge.bat (or python claude_bridge.py) and keep the terminal visible — structured logs appear there while the bridge is running.
Changing the port
The bridge binds :5001 by default. Change it in the Settings tab — the value persists to bridge_settings.json, but you'll need to restart the bridge for the new port to take effect (the GUI shows a Restart bridge reminder when there's a pending change).

Tips & gotchas

Images
SillyTavern sends base64 images. The bridge saves them to temp_images/ and has a separate Claude call describe them before the turn; the descriptions are cached and added to the turn as text.
Tool calling
Extensions like TunnelVision route through the tool-calling toggle. Disable it if you're getting strange outputs or the extension is in an odd state.
Streaming
With streaming on in SillyTavern, the reply streams as Claude writes it: the thinking summary first (shown when "Request model reasoning" is on and Include Thinking is enabled), then the reply. Requests with tool calling or a JSON schema arrive in one piece at the end.
Character key
The History tab and the bridge's log label each roleplay turn with a key for its character: 16 characters of MD5 over the character's name as SillyTavern wraps the card's fields, or else over the first 2000 characters of the greeting.
Debug logs
Enable Debug Output in Settings to see every incoming request structure, image detection passes, and prompt sizes in the bridge terminal. Essential when wiring up new SillyTavern extensions.

Prompts

Your SillyTavern prompt (preset, character card, persona, lore, Post-History Instructions) is what tells Claude how to write. The bridge adds only a short frame explaining how SillyTavern's messages are laid out, plus the optional style notes and the Creativity text below.

Style Notes optional

How This Works

  • System prompt: the bridge frame, your style notes (if any), SillyTavern's prompt, the Creativity mode, and tool definitions. It stays fixed for a CLI session, which keeps Claude's earlier thinking valid and the prompt cache warm.
  • Chat: a new session gets the chat so far as a transcript; later turns send only your new message. Lore or notes that SillyTavern adds or changes mid-session are added to that turn, and Post-History Instructions are re-sent when they change.
  • Thinking: Claude always thinks before replying; the Effort setting controls how much. No prompt asks it to write its reasoning out. With "Include Thinking" on, its thinking summary goes to SillyTavern's reasoning block.

Character Memory

A character remembers another chat only where you ask for it: connect that chat to the chat it should be remembered in, or bind the character to a persona so they remember the chats with that persona you pick, and every new one. The bridge reads those chats from SillyTavern's folder, and Sonnet recaps them from each character's point of view where the character is in them, and as a plain account where they aren't. Memories count over what the card says about the character's history. How it works is below.

Connections

Each box is a chat, with the chats it remembers joined under it. Any chat in SillyTavern can be connected to any other, a group chat too. A character who wasn't in the remembered chat gets it as background. In a group chat everyone remembers it, unless you pick who.

Character

Per character: persona bindings, their cards, and every chat of theirs with its recap.

Cards:

Persona bindings

A bound character remembers, in each chat with that persona, the chats you tick under it, plus every new chat with the persona from the day you bind (branches only if you tick them). A chat never brings in itself or its own branches.

Chats

The character's own chats and their group chats, each with the chats it's connected to. Open one to read or edit its recap, or to connect chats to it.

What other chats get

A chat remembered in another chat, through a connection or a binding, comes either as one synopsis or as its chapters. In chapters mode Sonnet divides a chat of three parts or more (81 messages and up) by event, and each connection or binding can leave chapters out: open its recap to choose. Both are written from the chat's part recaps, and part recaps already shorter than the target are passed on as they are.

How it works

Setup
Turn on Character Memory in Settings, and install the bridge's SillyTavern extension, Bridge Memory: run st-extension/install.sh from the bridge's folder and reload SillyTavern. The extension adds which chat, persona and character each request is for, which nothing else in a request says. Memory skips turns without it. The status at the top of this tab says whether it has been heard from.
Recaps
The bridge reads a chat's file from SillyTavern's folder, and Sonnet recaps it 40 messages at a time, each part with the previous part's recap for context. A part the character has a message in is recapped from their point of view. A part they have no message in is recapped as a plain account of what happened, which never puts them in it, and every character who isn't in that part shares the one account. Hidden and empty messages are left out. Recaps are built in the background when a chat that needs them is used or opened in SillyTavern, or when you ask here, and a reply uses whatever is ready; the rest arrives on later replies. A part is recapped again only when its messages change, and a branch shares its parent's recaps up to the branch point. Open a chat below to read what the character remembers of it; Recap beside a connected chat, or a chat in a binding, shows it in place. Edit lets you rewrite any part, the synopsis or a chapter; Redo has it written again. An edit of a synopsis or chapter lasts until a part it's written from changes.
Synopsis or chapters
Other chats don't get a chat's part recaps but what's written from them, set at the top of this tab. Synopsis: one recap of the whole chat in about the number of words you set. Chapters: Sonnet divides a chat of three parts or more (81 messages and up) into chapters by event, at part boundaries, once for every character, titles them, and writes each in about the number of words you set. A chat too short for chapters comes whole. When the chat grows, only its last chapter is divided again, so the earlier ones keep their place and what you chose for them. Untick chapters per connection (in its recap under Connections, or in the chat) and per binding; a binding's choice holds in all its chats. Part recaps already within the word target go as they are, with no call. Changing the mode or word target has each chat written again the next time it's needed; the division into chapters is kept when only the word target changes.
Earlier in a chat
When SillyTavern leaves a chat's oldest messages out to fit the context, the recap of those messages comes in instead.
Connections
Connect any chat to any other under Connections, or from a chat's dialog: the chat that remembers, the chat it remembers, and who remembers it. In a one-character chat, that's the character. In a group chat it's everyone in it, members who join later included, or only the members you tick, so a private scene can stay with the one character who was in it. A character who isn't in the remembered chat at all gets it as background: the memory says they weren't there and know only what they'd have heard or been told. In a group chat, Leave out for in one member's view of the chat keeps a connection for everyone from that member.
Persona bindings
Bind a character to a persona, then tick the chats with that persona they should remember; Select all ticks every chat with it. From then on each new chat with that character and persona joins by itself. Branches don't, as they're alternate timelines; tick them if you want them. In every chat with the persona, the character remembers all the ticked chats except the chat itself and its own branches. A chat's Don't bring in through bindings keeps it out everywhere; Leave out here keeps one chat's memory out of one other chat.
What the model gets
A new CLI session gets a <character_memory> block before the transcript: the recap of this chat's earlier part, then the other chats' synopses or chapters, oldest first, each saying who was there, or that the character wasn't and it's background. Newest chats get theirs while 24,000 characters last; a chat whose chapters don't all fit loses its earliest ones, and older chats that don't fit are left out. After that, each reply carries only recaps that are new or changed, and a note when one is dropped. The block says the memories count over the card's description and scenario about the character's history and relationships. Only the character whose reply it is gets their memories; in a group chat each member has their own CLI session.
Conflicts
Once a chat with memories from other chats has your first message, Sonnet compares how it starts (its greeting, your first message and its Author's Note) with the memories of chats the character was in. Background from chats they weren't in isn't checked. If they clash, say the chat has them meet as strangers or makes them siblings, SillyTavern shows it after the next reply: keep the memories, or untick the ones to leave out of this chat. The chat here shows it too.
Cards
A character can have several cards, such as the same person on cards from different creators. Add the others to the character, and their chats and memories become one character's. Removing a card takes its chats back with it.
Cost
Nothing runs per reply. Recapping takes one Sonnet call per 40 messages, once, plus one per 40 messages for the plain account of parts a character isn't in, shared by everyone who isn't. A connection for everyone in a group chat is recapped for each member, so the dashboard asks first with an estimate. A synopsis takes one more, chapters one to divide the chat plus one per chapter (none for a synopsis or chapter short enough already), and a conflict check one. They count against your plan like any other call and are listed on the History tab under Character Memory.
