Welcome

A subprocess bridge between SillyTavern and Claude Code CLI. SillyTavern sends OpenAI-compatible requests to this server; the bridge translates them, frames SillyTavern's prompt for the CLI, pipes the result through claude -p, and returns the response. Everything in this interface controls how that translation works.

Getting started

Endpoint
Point SillyTavern's Chat Completion API (Custom, OpenAI-compatible) at http://localhost:5001/v1. When the bridge runs with BRIDGE_API_KEY set, use that key as the API key.
Model
Choose the model in the Settings tab, or pick "Use SillyTavern's model" there to take the one selected in SillyTavern's connection.
Start command
Run run_bridge.bat (or python claude_bridge.py) and keep the terminal visible — structured logs appear there while the bridge is running.
Changing the port
The bridge binds :5001 by default. Change it in the Settings tab — the value persists to bridge_settings.json, but you'll need to restart the bridge for the new port to take effect (the GUI shows a Restart bridge reminder when there's a pending change).

Per-character summaries

Every character gets its own summary bucket. The bridge identifies a character by hashing the first assistant message (the character's greeting) and stores summaries under auto_<hash> cache keys. Switching characters in SillyTavern auto-swaps buckets — no manual cache clearing, and two characters can't cross-contaminate each other's narrative.

If you edit a character's greeting mid-chat, the hash changes and a new bucket appears. Rare, but worth knowing. Legacy pre-per-character entries (those with the bare auto key) auto-migrate to the current character on the next auto-summary update — you'll see a ⚠ flag in the Summary Cache panel while they exist.

Editing prompts

The bridge's internal prompts — summarization, condensation, chunk processing — live as editable Markdown files in the prompts/ directory next to claude_bridge.py:

summarize_incremental
Runs each time the auto-summary threshold is hit. Takes new messages, returns a narrative chunk that gets appended to the existing summary.
condense
Fires when a summary grows past auto_summary_max_length characters. Narrative-preserving condensation targeting ~60% of the original length.
summarize_chunk
Used by both chunking paths (the live /v1/chat/completions chunking mode and the /api/summary/generate file-based mode) for individual chunk summaries.
condense_chronological
Final pass in the file-based summary generator when combined chunks exceed 50K characters. Organizes events chronologically across the whole chat.

Templates use Python {variable} placeholders. Edits apply on the next request — no server restart needed, because load_prompt() re-reads the file every call. If you need a literal brace in a prompt (rare), double it: {{ and }}.

The roleplay framing is not in this folder — it's the BRIDGE_FRAME constant in claude_bridge.py. The Prompts tab shows where it goes.

Tips & gotchas

Images
SillyTavern sends base64 images. The bridge saves them to temp_images/ and has a separate Claude call describe them before the turn; the descriptions are cached and added to the turn as text.
Tool calling
Extensions like TunnelVision route through the tool-calling toggle. Disable it if you're getting strange outputs or the extension is in an odd state.
Streaming
With streaming on in SillyTavern, the reply streams as Claude writes it: the thinking summary first (shown when "Request model reasoning" is on and Include Thinking is enabled), then the reply. Requests with tool calling or a JSON schema arrive in one piece at the end.
Chunking
One-shot by design: enable it, send one message, the bridge splits the conversation, summarizes every chunk, seeds the character's auto-summary bucket, and auto-disables. Use it after importing a long chat, not for every turn. The Cancel button disarms it without sending a request.
Character key
The hash is 16 characters of MD5 over the first 2000 chars of the greeting. Stable across turns. If you use the backup zip to restore state, cache keys remain valid.
Debug logs
Enable Debug Output in Settings to see every incoming request structure, image detection passes, and prompt sizes in the bridge terminal. Essential when wiring up new SillyTavern extensions.

How This Works

  • System prompt: the bridge frame, your style notes (if any), SillyTavern's prompt, the Creativity mode, and tool definitions. It stays fixed for a CLI session, which keeps Claude's earlier thinking valid and the prompt cache warm.
  • Chat: a new session gets the chat so far as a transcript; later turns send only your new message. Lore or notes that SillyTavern adds or changes mid-session are added to that turn, and Post-History Instructions are re-sent when they change.
  • Thinking: Claude always thinks before replying; the Effort setting controls how much. No prompt asks it to write its reasoning out. With "Include Thinking" on, its thinking summary goes to SillyTavern's reasoning block.

Auto-Summary

Cuts per-request token usage dramatically on long RPs. Without it, SillyTavern re-sends your entire message history every turn — at message 200, that's the whole conversation going up the pipe on every single reply. Auto-summary replaces old messages with a condensed narrative digest the bridge keeps per character, so each request sends summary + last 15 messages instead of the full backlog. The one-time cost of generating the summary is paid back many times over the next dozens of turns, and because the summary + system prompt stay stable across requests, Claude's prompt cache kicks in and most of those tokens come back as cheap cache reads instead of full reads. New events get appended without losing old ones, and each character's story lives in its own bucket — switching characters won't cross-contaminate context.

Character Memory

A character remembers another chat only where you ask for it: connect that chat to the chat you're in, or bind the character to a persona so they remember the chats with that persona you pick, and every new one. The bridge reads those chats from SillyTavern's folder and Sonnet recaps them from the character's point of view. Memories count over what the card says about the character's history. How it works is below.

Character

Cards:

Persona bindings

A bound character remembers, in each chat with that persona, the chats you tick under it, plus every new chat with the persona from the day you bind (branches only if you tick them). A chat never brings in itself or its own branches.

Chats

The character's own chats and their group chats. Open one to read or edit its recap, connect other chats to it, or see what it brings in.

How it works

Setup
Turn on Character Memory in Settings, and install the bridge's SillyTavern extension, Bridge Memory: run st-extension/install.sh from the bridge's folder and reload SillyTavern. The extension adds which chat, persona and character each request is for, which nothing else in a request says. Memory skips turns without it. The status at the top of this tab says whether it has been heard from.
Recaps
The bridge reads a chat's file from SillyTavern's folder, and Sonnet recaps it from the character's point of view, 40 messages at a time, each part with the previous part's recap for context. Hidden messages are left out. A chat whose recap is long also gets a short one (up to 150 words). Recaps are built in the background when a chat that needs them is used or opened in SillyTavern, or when you ask here, and a reply uses whatever is ready; the rest arrives on later replies. A part is recapped again only when its messages change, and a branch shares its parent's recaps up to the branch point. Open a chat below to read what the character remembers of it; Recap beside a chat in a binding or in another chat's memories shows it in place. Edit lets you rewrite any part or the short recap; Redo has a part recapped again.
Earlier in a chat
When SillyTavern leaves a chat's oldest messages out to fit the context, the recap of those messages comes in instead. Not with auto-summary on, which already summarizes them.
Connections
Open a chat below and connect another chat to it: the character remembers that chat in this one. Connections are per character, so in a group chat only that member remembers it. Use them for one-off encounters, like a private scene only that character was in.
Persona bindings
Bind a character to a persona, then tick the chats with that persona they should remember; Select all ticks every chat with it. From then on each new chat with that character and persona joins by itself. Branches don't, as they're alternate timelines; tick them if you want them. In every chat with the persona, the character remembers all the ticked chats except the chat itself and its own branches. A chat's Don't bring in through bindings keeps it out everywhere; Leave out here keeps one chat's memory out of one other chat.
What the model gets
A new CLI session gets a <character_memory> block before the transcript: the recap of this chat's earlier part, then the other chats', oldest first, each saying who was there. Newest chats get their full recap while 24,000 characters last, then their short one; older chats that don't fit are left out. After that, each reply carries only recaps that are new or changed, and a note when one is dropped. The block says the memories count over the card's description and scenario about the character's history and relationships. Only the character whose reply it is gets their memories; in a group chat each member has their own CLI session.
Conflicts
Once a chat with memories from other chats has your first message, Sonnet compares how it starts (its greeting, your first message and its Author's Note) with those memories. If they clash, say the chat has them meet as strangers or makes them siblings, SillyTavern shows it after the next reply: keep the memories, or untick the ones to leave out of this chat. The chat here shows it too.
Cards
A character can have several cards, such as the same person on cards from different creators. Add the others to the character, and their chats and memories become one character's. Removing a card takes its chats back with it.
Cost
Nothing runs per reply. Recapping takes one Sonnet call per 40 messages, once; a short recap and a conflict check take one call each. They count against your plan like any other call and are listed on the History tab under Character Memory.
